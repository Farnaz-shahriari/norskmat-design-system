# design-sync notes, Norsk Mat design system

Repo-specific facts for the next /design-sync run. Read this first.

## Setup

- [GENERAL] The package has no compiled JS entry. `main` points at `src/index.ts`, the build emits only `dist/*.d.ts` and `dist/norskmat.css`. The converter bundles the TS source directly: `cfg.entry` is `src/index.ts`, and the converter is always run with `--entry ./src/index.ts --node-modules ./node_modules`.
- [GENERAL] Run `npm run build` before the converter whenever stories change, not only components. Tailwind scans the whole repo root, so `dist/norskmat.css` is what carries the layout classes the stories and the platform decorator use. A story class missing from the previews means a stale `dist/`.
- [GENERAL] The platform decorator (all four themes side by side, or one theme class on `<html>`) is `.storybook/with-platform.tsx`, listed in EVERY story file's meta `decorators`, not in `preview.tsx`. Why: the converter applies preview-wide decorators with a fixed context (initial globals, no story parameters), so a story pinned to one platform still rendered all four columns in the preview, four open dialogs stacked, all KSL. Meta decorators get the story's own `parameters`. A new story file must list `decorators: [withPlatform]` in its meta.
- [GENERAL] Overlay stories (open Dialog, Select, AlertDialog, Sheet, Tooltip, DropdownMenu, Popover) pin one platform with `...pinPlatform("<id>")` from `.storybook/platforms.ts`. It sets the global (Storybook toolbar lock) and `parameters.platform` (what withPlatform reads, and the only one previews see). Pinned mode wraps the story in `min-h-screen`: the compare harness screenshots `#storybook-root`, and a short root cropped the centred dialog out of the reference.
- [GENERAL] `.storybook/preview.tsx` must not import CSS: the converter bundles it with esbuild, and the fonts behind `preview.css` failed that bundle ("No loader is configured for .woff2"). The stylesheet loads through `previewAnnotations` in `.storybook/main.ts` and `.storybook/preview-styles.ts` instead.
- The npm cache at `~/.npm` has root-owned entries on this machine (EACCES). Installs used `--cache /private/tmp/claude-502/npm-cache` as a workaround. Fix with `sudo chown -R 502:20 ~/.npm`.
- Story title "Tabs" maps to the `TabGroup` export (`cfg.titleMap`); the stories render a whole tab row.
- [GENERAL] Groups in the Claude Design pane come from the story title: the segment before the component name. Titles are `Components/<Group>/<Name>` with six groups, Actions, Forms, Info, Layout, Navigation, Overlays. A new story file picks its group by its title; a retitle edits the story source, so that component re-grades once. Per-component docs with `category:` frontmatter would also regroup, but a doc body REPLACES the synthesized `.prompt.md` (story examples and variants are dropped), so docs are not the regroup tool here.
- [GENERAL] Foundation and theme cards are not components. `scripts/build-design-cards.mjs` (`npm run build:cards`, part of `cfg.buildCmd`) writes them into `design-cards/` (gitignored) laid out like the project root: `foundations/{colours,typography,spacing-and-shape,theme-explorer}.html` and `_preview/ThemeExplorer.js`. Each card's first line is `<!-- @dsCard group="..." viewport="WxH" name="..." -->`; the app reads `name` too (it shows in the manifest). The pages load `../styles.css` (the explorer also `../_vendor/react.js`, `../_ds_bundle.js`, `../_preview/ThemeExplorer.js`). Colours, Typography, Spacing and shape come from `tokens.css` via extract-tokens.mjs; the Theme explorer is `stories/examples/theme-explorer.tsx` compiled against `window.NorskmatDesignSystem`. These cards are outside the compare harness: verify them by rendering, e.g. a scratch copy of ds-bundle with design-cards/ laid over it, served locally.
- [GENERAL] The pane orders groups alphabetically, case-insensitive (the manifest's `cards` array is sorted that way). The user wants brand foundations first, then the Theme explorer, then the component groups, so the two card groups are "1. Foundations" and "2. Theme explorer" (constants at the top of the build script). A leading number is the only lever on order. Confirmed in the manifest on 2026-10-22.
- [GENERAL] The converter does not upload these cards: they are outside ds-bundle. After `npm run build:cards`, upload `design-cards/foundations/*.html` to `foundations/` and `design-cards/_preview/ThemeExplorer.js` to `_preview/ThemeExplorer.js` under their own plan (localDir = repo root), fenced like any push: sentinel, files, sentinel. Then the user reloads the project and the manifest must list the four cards. `cfg.guidelinesGlob` still has `design-cards/*` and the docs.mjs fork still accepts .html/.js, but the glob matches nothing now (the cards are in subfolders). Both were kept so this round moved no grade contracts; drop them at the next full re-verify.
- The Theme explorer is also the story `Examples/ThemeExplorer`, excluded from the component sync with `cfg.titleMap` `ThemeExplorer: null`. It has no withPlatform decorator on purpose; it switches brands itself.
- Run `npm run build` after editing the explorer: its Tailwind classes compile into `dist/norskmat.css` because Tailwind scans `stories/`; the generated `design-cards/` is gitignored and not scanned.

## Decisions

- Fonts, decided by the user on 2026-10-21: accept substitutes for `[FONT_MISSING]`. "Work Sans" and "Poppins" are fallbacks after Manrope in the KSL, Nyt Norge and Spesialitet stacks and never load, since Manrope ships. LokalMat's "Messina Serif" and "Sands" are not licensed; LokalMat renders in Georgia, the stand-in `tokens.css` declares, until real licensed files exist. Do not ship the Messina files found in the hand-built "Norsk Mat Design System" Claude Design project (some are named Trial) without a licence.
- Only storied components become documented components in the storybook shape. 30 components have stories (10 from the original Storybook step, 20 added for this sync); the rest of the library is in `_ds_bundle.js` but undocumented. To document more, write stories for them and re-sync.

## Grading

- [GENERAL] Every story renders inside the platform decorator: four themed columns in an auto-fit grid (min 280px). The preview page pads the story by 24px, so the grid usually wraps at 2 columns in the preview where the reference storybook shows 3 (or 1+3 vs 2+2). That is framing, not the component: grade on the components inside the columns. Cells inside a column can wrap differently for the same reason.
- [GENERAL] Page font, text colour and default border colour, since 2026-10-22 (Phase 0 of the Material 3 restyle, docs/m3-audit.md): the base layer of `tokens.css` sets `font-family: var(--font-family)` and `color: var(--foreground)` on `:root` and every theme class, and `border-color: var(--outline-variant)` as the default for every element. Before that the shipped CSS set none of them: text without a named type class and everything in a Radix portal rendered in the system font and #000, and a bare `border` drew in currentColor. `.storybook/preview.css` now sets only the page background, so Storybook shows what apps get. Not yet synced to Claude Design: the next sync shifts every preview slightly (inherited text, LokalMat's untyped text turns Georgia, Card/Alert/Table/Accordion/Sheet edges go light). It is styling, so grades carry; spot-check.
- The compare harness captures previews at 900x700. A side-by-side story taller than 700px in the preview's 2-column wrap is cut off at the bottom in the capture only (Card "With Dividers"). Grade on the visible part and the full KSL/Nyt Norge columns.
- [GENERAL] Until the next sync only: inherited text colour was framing too: `.storybook/preview.css` sets `body { color: var(--foreground) }`, the preview page sets none. Text and bare `border` (currentColor) that inherit from body render the theme's near-black in storybook (KSL rgb(26,28,22)) and #000 in the preview, at most ~35/255 per channel, invisible on the sheet. Hits portalled Dialog/AlertDialog content, Sheet labels and borders, the DropdownMenu kebab trigger. Popover/DropdownMenu panels set `text-popover-foreground` and are pixel-identical. Pixel-diff method: decode both raws on a canvas with the playwright in `.ds-sync/node_modules`; offset Popover by 24px.
- The Spesialitet page background (beige) only exists in Storybook (preview.css paints body with var(--background)). Backdrop and page tint differences in Spesialitet stories are framing.
- [GENERAL] When a delta looks width-caused, prove it before calling it framing: render the preview at a viewport that gives the storybook column width (900px storybook -> 948px preview, since the preview pads 24px each side). A throwaway playwright script serving ds-bundle and opening `components/<group>/<Name>/<Name>.html?story=<Export>` is enough (group = actions, forms, info, layout, navigation, overlays; the old components/components/ path 404s silently and the probe screenshots a blank ~3 KB page, so check the PNG before trusting it). Load playwright from `.ds-sync/` (createRequire on `.ds-sync/package.json`); the repo's own node_modules has none. Used to confirm TextInputField "Trenger utfylling".
- [GENERAL] Horizontally scrolling rows (TabGroup with `scrollable`, Table's overflow wrapper) show less in the narrower storybook columns: TabGroup's disabled "Arkiv" tab and TabLarge's "Vedlegg" scroll out of view, Table hides the Alvorlighet column. Framing; check the story source renders the hidden item on both sides.
- [GENERAL] The shrunk compare sheet invents small colour and icon deltas (LokalMat TabCompact indicator looked grey, Spesialitet ConnectedButtonGroup check looked broken; raw PNGs identical). Open raw/ before grading any small colour or icon difference close or mismatch.
- [GENERAL] Non-modal overlays (Tooltip, Popover) sit 24px further right and down in the preview capture than in storybook: `?story=` captures keep the preview page's `body{padding:24px}`, while modal overlays (Dialog, AlertDialog, Sheet, DropdownMenu, Select) lock scroll and react-remove-scroll-bar zeroes that padding. Framing; the product card already has no body padding. Radix collision avoidance can also place a tooltip differently near the left edge because of the shift.

## Re-sync risks


- [GENERAL] HTML/JS files under `guidelines/` stop the app's self-check. After the 2026-10-22 re-sync put the five design cards in `guidelines/design-cards/`, two full project reloads left `_ds_needs_recompile` in place and `_ds_manifest.json` stale (the old `components/components/` paths). Deleting only those five files and re-arming the sentinel let the next reload rebuild the index (six groups, 30 cards); the same cards then registered fine from `foundations/` with the script in `_preview/`. Never ship HTML or JS into `guidelines/`. After any upload, confirm the sentinel is gone and the manifest changed; a stale manifest is the only sign of this failure.
- A re-sync may treat `foundations/*` and `_preview/ThemeExplorer.js` as files it doesn't know (they are not in ds-bundle or the `_ds_sync.json` anchor). Before approving a re-sync plan, check it deletes neither; afterwards, list the project and re-upload the cards if they're gone.
- Every story file must list `decorators: [withPlatform]` in its meta. A new story file without it renders in the KSL root only and will not match storybook; one pinned without `pinPlatform()` renders four stacked overlays.
- Overlay cards depend on config: `cardMode: "single"` with `primaryStory: "OpenKSL"` for AlertDialog, Dialog, DropdownMenu, Popover, Select, Sheet, Tooltip, and `cardMode: "column"` for DatePicker. Renaming an `OpenKSL` story export breaks that card silently.
- Run `npm run build` AND rebuild `.design-sync/sb-reference` whenever stories or `src/` change; they must move together. `dist/norskmat.css` is what carries story layout classes.
- The page font and text colour are fixed in `tokens.css` (2026-10-22) but not yet synced. `.design-sync/conventions.md` already dropped the `fontFamily` root workaround and lists `title-small` and `body-small`; ship both together on the next sync, and re-validate the class names against the fresh build.
- `.design-sync/conventions.md` names utility classes that exist in the compiled CSS today only because a component or story uses them (incl. `bg-[var(--error)]` and friends, from stories/card and badge). Re-validate every name against the fresh build on each sync; a class that stops being used anywhere drops out of `styles.css`.
- Partially verified: several side-by-side stories are taller than the 700px preview capture, so the bottoms of the Spesialitet/LokalMat columns were judged via the full KSL/Nyt Norge columns (Card "With Dividers", RadioGroup "States", Textarea "States", Accordion "Multiple open"). Sibling-trusted stories exist for Table, Accordion, Breadcrumb, Pagination, ConnectedButtonGroup.
- Toolchain at this sync: Storybook 10.6.1, Vite 7.3.7, @tailwindcss/vite 4.1.11 (must match Tailwind 4.1.11), Playwright 1.64.0 with its Chromium, converter deps esbuild 0.28.2, ts-morph 28.0.0, @types/react 18.3.12 in `.ds-sync/`.
- Guidelines come from `skills/norsk-mat-design-system/references/*.md` (`cfg.guidelinesGlob`), not `docs/`.
- Known library issues found during this sync, reported to the user. Fixed since: page font and overlay text colour (2026-10-22, tokens.css base layer). Still open: DatePicker trailing text overflows narrow fields, TextInputField label collapses beside the "Trenger utfylling" chip below ~290px (viewport media query, not container width). ConnectedButtonGroup does not shrink or truncate its segments: below ~300px a long label ("Mindre alvorlig") wraps and spills out of the pill outline.
